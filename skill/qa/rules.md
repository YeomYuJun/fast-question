# Q&A 등록 규칙

이 파일이 fast-question 등록 규칙의 원본이다. qa Skill, qa-harvest Skill, MCP 서버 안내문은 이 파일을 따른다.
Claude 가 MCP 로 쓸 때 `kb_add`·`kb_update`·`kb_evidence` 는 답변 문장 수와 민감 정보를 검사해 위반이면 거부한다. 거부 메시지를 보고 고쳐서 다시 부른다.

## 넣는 것

- 이유: 코드·설정·결정이 왜 그렇게 되어 있는지
- 동작 조건: 언제 무엇이 일어나는지, 실패하면 어떻게 되는지
- 절차: 무엇을 하려면 어떤 명령을 어떤 순서로 쓰는지
- 오류의 원인과 처리
- 설정 키·값·코드의 뜻
- 결정과 그 근거(누가 언제 정했는지)
- 작업 중에 나와 다시 물을 만한 일반 지식

## 넣지 않는 것

- 진행 상태, 할 일, 일정. 진행 원장과 이슈 트래커가 맡는다
- 이름만 봐도 아는 것(예: `UserService 는 사용자 서비스인가`)
- 코드나 문서를 그대로 옮긴 것
- 확인하지 않은 추정. 확인하지 못했으면 등록하지 않는다
- 이 대화에만 해당하는 질문(예: `방금 그 명령은 왜 실패했나`)
- 비밀번호, 토큰, API 키, 개인 키
- 주민등록번호, 전화번호, 이메일 주소 같은 개인정보
- IP 주소 같은 내부 망 값. 값 대신 그 값이 적힌 위치(파일·시트)와 절차를 쓴다. 루프백(`127.0.0.1`)은 넣어도 된다

## 질문

- 한 줄, 150자 이하. 한 질문에 한 사실만 묻는다. 답이 여러 개면 질문을 나눈다.
- 질문만 읽어도 무엇에 대한 것인지 알 수 있게 쓴다. 대상 이름(파일, 클래스, 설정 키, 명령, 개념)을 넣는다.
  대상이 일반 명사(검색, 분류, 웹 서버, 저장소, 배포)면 시스템이나 프로젝트 이름을 붙인다.
  - 나쁨: `검색 계층의 순서는`
  - 좋음: `fast-question 검색 계층의 순서는?`
- 묻는 문장으로 쓴다. 물음표는 붙여도 되고 붙이지 않아도 된다.
- 문형을 맞춘다. 같은 문형이어야 검색어도 같아진다.
  `X 가 Y 하는 이유는?`, `X 하려면?`, `X 가 실패하면?`, `X 의 뜻은?`, `X 와 Y 의 차이는?`, `X 는 언제 Y 하나?`

## 답변

- 1~2문장, 400자 이하, 2줄 이하. 서술형으로 단정한다("~다.").
- 무엇이 무엇을 해서 어떻게 되는지 쓴다. 비유를 쓰지 않고 얼버무리지 않는다.
- 경로, 식별자, 명령은 원문 그대로 쓴다.
- 측정값, 버전, 날짜에 따라 바뀌는 내용에는 기준일이나 버전을 붙인다(예: `2026-10-08 실측 2.5초`).

## 분류

- 대분류는 작업 주제(프로젝트·사업 이름, `일반 지식`), 중분류는 대상(모듈, 시스템, 기술)이다.
- `kb_categories` 에 맞는 분류가 없으면 묻지 않고 `kb_add_category` 로 만든다. 대분류가 있으면 그 아래 중분류만 만든다.

## 근거

| 사실을 확인한 곳 | 근거 |
|---|---|
| 이 세션에서 읽은 로컬 파일(코드, 설정, md) | `{"kind": "auto", "path": "<절대경로>", "anchor": "<심볼이나 찾을 문자열>"}` |
| 문서 파일(xlsx, hwp, pdf, docx) | `auto` + `path`. 시트 이름이나 절 제목을 `anchor` 로 쓴다 |
| git 이력(커밋) | 그 사실이 지금 남아 있는 파일을 `auto` 로 달고, 답변에 커밋 sha 앞 7자리를 쓴다 |
| 웹 문서 | `{"kind": "url", "url": "<주소>"}` |
| 사람에게 확인 | `{"kind": "note", "text": "누가 언제 어떻게 확인했는지"}` |
| 일반 지식 | 근거 없음 |

- 이 세션에서 읽지 않은 파일은 근거로 달지 않는다.
- git 저장소 안의 파일은 `auto` 가 git 근거로 기록된다.

## 용어

- 형태소 분석이 잘못 자르는 고유명사(시스템 이름, 사업 이름)는 등록 전에 `kb_dict` action=user_word_add 로 넣는다. 색인을 다시 만든다.
- 같은 뜻의 다른 표기(규칙/룰, NAS/스토리지)는 `kb_dict` action=synonym_add 로 묶는다.
