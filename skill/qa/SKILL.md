# qa

fast-question 은 사용자가 작업 중 생긴 질문과 답을 1~2줄로 쌓는 로컬 DB 다. 화면은 http://127.0.0.1:8765 이다.
도구는 MCP 서버 `fast-question` 의 `kb_*` 다. 도구가 목록에 없으면 사용자에게 `claude mcp list` 로 연결 상태를 확인해 달라고 하고 멈춘다.

## 등록 (`/qa`, "Q&A 로 남겨")

1. 대화에서 질문 1줄(150자 이하)과 답변 1~2줄(400자 이하)을 뽑는다.
   - 사실만 쓴다. 비유를 쓰지 않는다. 무엇이 무엇을 해서 어떻게 되는지를 쓴다.
   - 한 질문에 답이 여러 개면 질문을 나눠 여러 건으로 등록한다.
2. `kb_categories` 로 분류를 고른다. 맞는 분류가 없으면 사용자에게 이름을 묻고 `kb_add_category` 로 만든다.
3. 근거를 정한다.
   - 이 세션에서 로컬 파일을 읽어 확인한 사실: `{"kind": "auto", "path": "<절대경로>", "anchor": "<심볼이나 찾을 문자열>"}`. git 저장소 안이면 자동으로 git 근거가 된다.
   - 사람에게 확인한 사실: `{"kind": "note", "text": "누가 어떻게 확인했는지"}`
   - 일반 지식(k8s 개념, 수학 등): 근거 없이 등록한다.
   - 이 세션에서 읽지 않은 파일을 근거로 달지 않는다.
4. `kb_search` 로 같은 질문이 있는지 본다.
   - 있으면 `kb_get` 으로 version 을 읽고 `kb_update` 로 고친다. `reason` 에 고친 이유를 적는다.
   - 없으면 `kb_add`. `similar_found` 가 오면 후보를 보고 다른 질문일 때만 `force=true` 로 다시 부른다.
5. 사용자에게 등록·수정한 질문과 주소(`http://127.0.0.1:8765/#qa/<id>`)를 한 줄씩 알린다.

## 조회 (`/qa <검색어>`, "qa 에서 찾아봐")

1. `kb_search` 를 부른다. `hits` 의 `tier` 는 exact(그대로 일치), synonym(동의어), morph(활용형·조사 차이)다.
2. 0건이면 `similar` 를 보고, 표현을 바꿔 두 번까지 다시 검색한다.
3. 결과를 질문·답변 그대로 보여 준다. `evidence_state` 가 `stale` 이면 "근거 파일이 기록 뒤에 바뀌어 다시 확인이 필요하다"고 같이 말한다.

## 근거 재확인 ("qa 근거 다시 확인해")

1. `kb_recheck` 로 판정한다. `stale` 항목은 근거 파일을 다시 읽어 답변이 여전히 맞는지 본다.
2. 답변을 고쳐야 하면 `kb_update`, 맞으면 그대로 둔다. 그다음 `kb_evidence` (action=recapture)로 근거를 지금 상태로 다시 기록한다.

## 사전

- 같은 뜻의 다른 표기(규칙/룰, NAS/스토리지)를 찾게 하려면 `kb_dict` action=synonym_add.
- 형태소 분석이 잘못 쪼개는 고유명사(망연계 등)는 `kb_dict` action=user_word_add. 색인을 다시 만든다.
