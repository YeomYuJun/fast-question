# qa

fast-question 은 사용자가 작업 중 생긴 질문과 답을 1~2줄로 쌓는 로컬 DB 다. 화면은 http://127.0.0.1:8765 이다.
도구는 MCP 서버 `fast-question` 의 `kb_*` 다. 도구가 목록에 없으면 사용자에게 `claude mcp list` 로 연결 상태를 확인해 달라고 하고 멈춘다.

사람은 등록분을 검토하지 않는다. 등록은 아래 양식으로 Claude 가 끝까지 처리하고, 중간에 사용자에게 묻지 않는다.
무엇을 넣고 무엇을 넣지 않는지, 질문·답변·분류·근거 양식은 이 폴더의 [rules.md](rules.md) 가 원본이다. 등록 전에 읽는다.

## 등록 (`/qa`, "Q&A 로 남겨")

1. 대화에서 질문과 답변을 뽑는다. rules.md 의 "넣지 않는 것" 에 해당하면 등록하지 않는다. 한 질문에 답이 여러 개면 질문을 나눠 여러 건으로 등록한다.
   - 질문: 한 줄, 150자 이하의 묻는 문장. 질문만 읽어도 대상이 식별되게 대상 이름을 넣는다. 물음표는 필수가 아니다.
     예: `.part 확장자를 쓰는 이유는?`, `NasFileStorage 가 쓰기 전에 여유 공간을 검사하는 이유는?`
   - 답변: 1~2문장, 400자 이하. 서술형으로 단정해서 쓴다("~다."). 무엇이 무엇을 해서 어떻게 되는지를 쓴다. 비유를 쓰지 않고 얼버무리지 않는다. 경로와 식별자는 원문 그대로 쓴다.
2. 분류를 고른다.
   - `kb_categories` 를 보고 맞는 분류를 고른다.
   - 맞는 것이 없으면 묻지 않고 `kb_add_category` 로 만든다. 대분류는 작업 주제(프로젝트·사업 이름, `일반 지식`), 중분류는 대상 이름(모듈, 시스템, 기술)이다. 대분류가 이미 있으면 그 아래 중분류만 만든다.
3. 근거를 정한다(rules.md "근거" 표).
   - 이 세션에서 직접 읽은 로컬 파일로 확인한 사실: `{"kind": "auto", "path": "<절대경로>", "anchor": "<심볼이나 찾을 문자열>"}`. git 저장소 안이면 자동으로 git 근거가 된다.
   - 사람에게 확인한 사실: `{"kind": "note", "text": "누가 어떻게 확인했는지"}`
   - 일반 지식(k8s 개념, 수학 등): 근거 없이 등록한다.
   - 이 세션에서 읽지 않은 파일은 근거로 달지 않는다.
4. `kb_search` 로 같은 질문이 있는지 본다(0건이면 표현을 바꿔 한 번 더).
   - `kb_add`·`kb_update` 가 형식 규칙 위반(답변 3문장 이상, 비밀값·개인정보·IP 주소)으로 거부하면 메시지대로 고쳐 다시 부른다.
   - 같은 내용이 있으면 `kb_get` 으로 version 을 읽고 `kb_update` 로 고친다. `reason` 에 고친 이유를 적는다.
   - 없으면 `kb_add` 한다. `similar_found` 가 오면 후보를 직접 비교한다.
     - 같은 사실을 묻는 질문이면 그 후보를 `kb_update` 한다(답이 더 정확해지는 경우만).
     - 다른 사실이면 `force=true` 로 다시 부른다.
5. 끝나면 등록·수정한 건마다 한 줄씩만 보고한다. 형식: `등록: <질문> http://127.0.0.1:8765/#qa/<id>` 또는 `수정: ...`.

## 조회 (`/qa <검색어>`, "qa 에서 찾아봐")

1. `kb_search` 를 부른다. `hits` 의 `tier` 는 exact(그대로 일치), synonym(동의어), morph(활용형·조사 차이)다.
2. 0건이면 `similar` 를 보고, 표현을 바꿔 두 번까지 다시 검색한다.
3. 결과를 질문·답변 그대로 보여 준다.
4. 결과에 `evidence_state` 가 `stale`(근거 파일이 기록 뒤에 바뀜)인 항목이 있으면 사용자에게 넘기지 않고 Claude 가 정리한다.
   - `kb_get` 으로 근거를 보고 근거 파일을 다시 읽는다.
   - 답이 틀렸으면 `kb_update` 로 고친다.
   - 그다음(답이 맞았어도) `kb_evidence` action=recapture 로 근거를 지금 상태로 다시 기록한다.
   - 고친 항목은 등록과 같은 형식으로 한 줄씩 보고한다.

## 근거 재확인 ("qa 근거 다시 확인해")

1. `kb_recheck` 로 판정한다. 근거 재검증은 web 서버가 하루 한 번 자동으로도 돈다.
2. `stale` 항목은 조회 4번과 같이 처리한다. `unknown`(판정 불가)은 근거 경로가 없어진 경우가 많다. 경로를 찾아 `kb_evidence` 로 새 근거를 달고 옛 근거는 archive 한다.

## 사전

- 같은 뜻의 다른 표기(규칙/룰, NAS/스토리지)를 찾게 하려면 `kb_dict` action=synonym_add.
- 형태소 분석이 잘못 쪼개는 고유명사(망연계 등)는 `kb_dict` action=user_word_add. 색인을 다시 만든다.
