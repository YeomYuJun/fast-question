# qa

fast-question 은 사용자가 작업 중 생긴 질문 한 줄과 짧은 답을 쌓는 DB 다. 화면은 {{FAST_QUESTION_URL}} 이다.
도구는 MCP 서버 `fast-question` 의 `kb_*` 다. 도구가 목록에 없으면 사용자에게 `claude mcp list` 로 연결 상태를 확인해 달라고 하고 멈춘다.

사람은 등록분을 검토하지 않는다. 등록은 아래 양식으로 Claude 가 끝까지 처리하고, 중간에 사용자에게 묻지 않는다.
무엇을 넣고 무엇을 넣지 않는지, 질문·답변·분류·근거 양식은 이 폴더의 [rules.md](rules.md) 가 원본이다. 등록 전에 읽는다.

## 등록 (`/qa`, "Q&A 로 남겨")

1. 대화에서 질문과 답변을 뽑는다. rules.md 의 "넣지 않는 것" 에 해당하면 등록하지 않는다. 한 질문에 답이 여러 개면 질문을 나눠 여러 건으로 등록한다.
   - 질문: 한 줄, 150자 이하의 묻는 문장. 질문만 읽어도 대상이 식별되게 대상 이름을 넣는다. 물음표는 필수가 아니다.
     예: `.part 확장자를 쓰는 이유는?`, `NasFileStorage 가 쓰기 전에 여유 공간을 검사하는 이유는?`
   - 답변: 400자·6줄 이하. 첫 줄은 질문에 바로 답하는 1~2문장(120자 이하)이다. 덧붙일 사실이 있으면 둘째 줄부터 `- ` 로 시작하는 개조체 항목으로 한 줄에 하나씩 쓴다. 질문 문형별 모양은 rules.md "답변" 표를 따른다. 질문이 묻지 않은 대상은 쓰지 않는다.
2. 분류를 고른다.
   - `kb_categories` 를 보고 맞는 분류를 고른다.
   - 맞는 것이 없으면 묻지 않고 `kb_add_category` 로 만든다. 대분류는 작업 주제(프로젝트·사업 이름, `일반 지식`), 중분류는 대상 이름(모듈, 시스템, 기술)이다. 대분류가 이미 있으면 그 아래 중분류만 만든다.
3. 근거를 정한다(rules.md "근거" 표).
   - 이 세션에서 직접 읽은 로컬 파일로 확인한 사실: `{"kind": "auto", "path": "<절대경로>", "anchor": "<심볼이나 찾을 문자열>"}`. git 저장소 안이면 자동으로 git 근거가 된다.
   - 사람에게 확인한 사실: `{"kind": "note", "text": "누가 어떻게 확인했는지"}`
   - 일반 지식(k8s 개념, 수학 등): 근거 없이 등록한다.
   - 이 세션에서 읽지 않은 파일은 근거로 달지 않는다.
   - 원격 서버에 HTTP 로 직접 연결한 경우(`claude mcp add --transport http`)는 파일 근거를 달 수 없다. url·note 근거만 쓴다.
4. `kb_search` 로 같은 질문이 있는지 본다(0건이면 표현을 바꿔 한 번 더).
   - `kb_add`·`kb_update` 가 형식 규칙 위반(답변 양식, 결정 경위·추정 표현, 비밀값·개인정보·IP 주소)으로 거부하면 메시지대로 고쳐 다시 부른다.
   - 같은 내용이 있으면 `kb_get` 으로 version 을 읽고 `kb_update` 로 고친다. `reason` 에 고친 이유를 적는다.
   - 없으면 `kb_add` 한다. `similar_found` 가 오면 후보를 직접 비교한다.
     - 같은 사실을 묻는 질문이면 그 후보를 `kb_update` 한다(답이 더 정확해지는 경우만).
     - 다른 사실이면 `force=true` 로 다시 부른다.
5. 끝나면 등록·수정한 건마다 한 줄씩만 보고한다. 형식: `등록: <질문> {{FAST_QUESTION_URL}}/#qa/<id>` 또는 `수정: ...`.

## 조회 (`/qa <검색어>`, "qa 에서 찾아봐")

1. `kb_search` 를 부른다. `hits` 의 `tier` 는 exact(그대로 일치), synonym(동의어), morph(활용형·조사 차이)다.
   - 질의 문법: 공백 = AND, `a | b` = OR, `-a` = 제외, `"a b"` = 구절, `q:a`·`a:a` = 질문만·답변만, `path:파일이름` = 그 파일을 근거로 단 항목.
   - 표현이 여럿 떠오르면 `queries` 에 한 번에 넣는다. 걸린 질의가 많은 항목이 앞에 온다(`matched`).
   - 글자 패턴(번호 형식, 오류 코드 등)이 필요할 때만 `regex=true` 로 정규식을 쓴다(200자 이하, `(a+)+` 같은 중첩 반복 금지). 사용자 검색창에는 정규식이 없다.
2. 0건이면 `similar` 를 보고, 표현을 바꿔(`queries`) 두 번까지 다시 검색한다.
3. 결과를 질문·답변 그대로 보여 준다.
4. 결과에 `evidence_state` 가 `stale`(근거 파일이 기록 뒤에 바뀜)인 항목이 있으면 사용자에게 넘기지 않고 Claude 가 정리한다.
   - `kb_get` 으로 근거를 보고 근거 파일을 다시 읽는다.
   - 답이 틀렸으면 `kb_update` 로 고친다.
   - 그다음(답이 맞았어도) `kb_evidence` action=recapture 로 근거를 지금 상태로 다시 기록한다.
   - 고친 항목은 등록과 같은 형식으로 한 줄씩 보고한다.

## 즉석 질문 (턴 문맥에 `[fast-question 지식 DB]` 안내가 붙은 경우)

사용자가 질문하면 전역 훅(`{{FAST_QUESTION_ROOT}}/hooks/ask_kb.py`, `~/.claude/settings.json` 의 UserPromptSubmit)이 KB 를 찾아 결과와 지시를 그 턴에 넣는다.
훅은 질문한 폴더가 KB 에 있는 프로젝트(대분류 이름과 같은 폴더, 또는 qa-harvest 로 구축한 경로)일 때만 등록 조건을 넣는다. 그 밖의 평시 질문에는 등록 안내가 없다.

1. "맞는 Q&A 가 있다": 그 답을 먼저 쓰고 항목 주소를 붙인다. `stale` 항목은 조회 4번처럼 정리한다.
2. "Q&A 가 없다. 등록하지 않는 것이 기본이다": 질문에 답한다. 안내의 세 조건(그 프로젝트의 코드·설정·절차·동작에 대한 질문, 이 세션에서 읽은 그 프로젝트 파일·명령 결과로 확인, 다시 물을 만한 사실)을 모두 만족할 때만 등록 절차 1~4로 저장하고, 응답 끝에 `등록: <질문> <주소>` 한 줄을 붙인다.
   - 질문 문장은 사용자 말을 그대로 쓰지 말고 rules.md 양식(대상 이름이 든 한 줄)으로 고친다.
   - 조건을 하나라도 못 채우면 저장하지 않고 안내를 언급하지 않는다. 일반 지식은 사용자가 `/qa` 로 요청할 때만 넣는다.
3. "비슷한 항목" 만 오면 같은 사실을 묻는지 비교한다. 같으면 그 항목을 답으로 쓴다.

## 근거 재확인 ("qa 근거 다시 확인해")

1. `kb_recheck` 로 판정한다. 근거 재검증은 web 서버가 하루 한 번 자동으로도 돈다.
2. `stale` 항목은 조회 4번과 같이 처리한다. `unknown`(판정 불가)은 근거 경로가 없어진 경우가 많다. 경로를 찾아 `kb_evidence` 로 새 근거를 달고 옛 근거는 archive 한다.

## 삭제·복원·분류 편집 (사용자가 요청한 경우만)

- Q&A 삭제는 `kb_archive` 다(화면의 삭제와 같다. 행은 남고 검색에서 빠진다). 되살릴 때는 `kb_search` 를 `include_archived=true` 로 불러 찾고 `kb_restore` 한다. 분류가 삭제된 항목은 `category` 에 옮길 분류를 준다.
- 분류 이름은 `kb_categories` 의 version 으로 `kb_rename_category` 해서 바꾼다.
- 분류 삭제는 하위 분류와 그 안의 Q&A 를 모두 함께 삭제한다. `kb_delete_category` 를 confirm 없이 불러 받은 `warning` 을 사용자에게 그대로 보여 주고, 사용자가 승인한 뒤에만 `confirm=true` 로 다시 부른다. 이 경우는 위 "묻지 않는다" 의 예외다.

## 사전

- 같은 뜻의 다른 표기(규칙/룰, NAS/스토리지)를 찾게 하려면 `kb_dict` action=synonym_add.
- 형태소 분석이 잘못 쪼개는 고유명사(망연계 등)는 `kb_dict` action=user_word_add. 색인을 다시 만든다.
